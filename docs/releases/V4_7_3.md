# Plane Alerts v4.7.3

v4.7.2 could stop applying its initial arrival guard before Telegram had delivered a message. It also allowed weak release signals and a hypothetical flight 18 km beyond the runway to defeat arrival protection. These defects affect Atatürk (LTBA/ISL), Istanbul (LTFM/IST), and the shared airport logic.

## Changes

- Scope the initial guard to actual persisted per-user message delivery. Recheck candidates after missing evidence and failed sends; preserve already delivered alerts across restarts.
- Keep unsent speculative qualifications out of cancellation-latch confirmation.
- Preserve the older bounded landing-turn hold when the aircraft is merely moving away from the airport, reports a climb, or has a possible runway extension. Independently detected go-around/missed approach still permits live reevaluation.
- Bound the landing path at the far runway end. Keep the 18 km airborne continuation in shadow diagnostics. Fresh observed entry and a pass underneath the remaining final approach still take precedence.
- Add throttled production decision logs with initial scope, landing CPA, release reason and effective suppression, without observer coordinates.

## Verification

Eight regression assertions failed on the old behavior before the fixes. Fifteen new tests cover the bypasses, LTBA/LTFM landing geometry, pass-before-touchdown controls, the monitor's send boundary, failed sends, persisted visible messages and speculative cancellation latches. The full local suite passed: **403 tests**, no skips. Compile checks, airport database verification, dependency consistency and all seven existing release benchmarks passed. Terminal assessment p95 was 0.856 ms; initial-hold p95 was 0.0075 ms in this local run. GitHub CI verifies the exact release commit separately.

## Evidence limits and rollback

The Error Museum distinguishes production log context from code-derived and physically consistent synthetic reproductions. Complete raw ADS-B tracks and authenticated notification snapshots were unavailable during investigation. No measured fleet-wide false-positive reduction is claimed; covered outcomes are required to measure that. Destination metadata alone still cannot prove the aircraft will land, and airport presence alone cannot veto a valid observed pass. No runtime AI or paid API dependency was added.

There are no database migrations. Rollback target is v4.7.2 commit `b332053a4e19e64892b6ddd59354e6420c1c1060`; redeploy that exact tested source to both services if needed, preserving persisted notification state. After either deployment, verify health version/commit, Railway logs, Telegram delivery errors and the five-second start interval. Rollback restores the known arrival-guard defects, so weigh that against any demonstrated new regression.
