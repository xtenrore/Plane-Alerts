# Plane Alerts v4.5.0 — Local ADS-B & Provider Resilience

## Summary

v4.5.0 changes the aircraft-ingestion layer while retaining the v4.4 prediction model and alert semantics. Local ADS-B is optional; public-only Railway operation remains supported when no local receiver is configured.

## Changes

- Added optional readsb, dump1090, dump1090-fa and ultrafeeder/tar1090 aircraft-JSON ingestion.
- Added canonical observation timing/source fields and field-level provenance while keeping the existing `timestamp` compatibility path.
- Added deterministic ICAO24 merging so request completion order cannot decide the live aircraft state.
- Fresh local position data is preferred; public data remains available for fallback, coverage expansion and safe metadata enrichment.
- Dynamic fields are only borrowed from another source when observation times are compatible and positions are physically plausible.
- Added per-provider latency, failures, timeout count, malformed-response count, rate-limit count, stale-position rate, aircraft count, circuit state and cooldown diagnostics.
- Added bounded circuit breakers, cooldown, recovery probes and `Retry-After`-aware rate-limit backoff.
- Critical-path provider timeouts now feed circuit state instead of being retried indefinitely without health memory.
- Corrected OpenSky region handling for latitude-scaled longitude, ±180° date-line splitting and near-pole searches.
- Kept the prediction model identifier at `4.4-observation-confirmations`; v4.5 does not introduce the v4.6 confidence/turn-aware predictor work.

## Local receiver configuration

`LOCAL_ADSB_URL` is optional. It can point directly to `aircraft.json` or to a receiver base URL. Supported receiver labels are `auto`, `readsb`, `dump1090`, `dump1090-fa` and `ultrafeeder`.

A receiver failure or malformed response never blocks the public provider path. Receiver URLs and Authorization values are not written into provider diagnostics.

## Verification scope

Automated coverage includes:

- canonical observed/received timestamps and missing freshness
- local receiver parsing and disabled mode
- local/public fallback and disagreement
- stale local vs fresh public selection
- deterministic merge order and conflicting callsign/position behavior
- provider timeout, circuit opening, cooldown and recovery
- rate-limit cooldown
- malformed receiver data and coordinates
- same ICAO across multiple providers/source switching
- equator, mid-latitude, Istanbul, high-latitude, ±180° and near-pole OpenSky bounds
- synthetic bounded concurrent local/public provider timing
- all inherited v4.4 replay, Error Museum, IST arrival and genuine-overhead regressions through the full pytest suite

The automated local-feed integration uses representative receiver fixtures and HTTP mocks. No physical SDR receiver is claimed as tested for this release; physical receiver behavior depends on the user's network/receiver deployment and remains a deployment-specific validation step.

## Production gate

Release only after full CI, terminal-arrival benchmark, v4.5 provider benchmark, dependency checks, Railway deployment of the exact tested commit, health/version/commit verification, Telegram verification, provider/fallback log inspection and post-deploy five-second cadence measurement.
