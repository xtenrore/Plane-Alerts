# Plane Alerts v5.2.0

Plane Alerts v5.2 makes prediction development measurable. It adds deterministic shadow-model evaluation, replay evaluation, live post-outcome evaluation, release-to-release metrics and conservative promotion evidence without changing which model controls live alerts.

## Scope classification

Before implementation, the v5.2 roadmap was classified against the existing production system:

- **Already solved / reused:** prediction-version identifiers, bounded Prediction Lab snapshots, v4.6 linear and turn-aware shadow candidates, Error Museum replay fixtures, optional-work isolation and operator diagnostics foundations.
- **Partial -> completed:** model comparison evidence and versioned prediction records.
- **Missing -> implemented:** explicit shadow feature flags, automatic replay evaluation, bounded live shadow evaluation, release-to-release model metrics, operator shadow reports and promotion-safety criteria.
- **Needs evidence:** cancellation accuracy and false-positive rates require coverage-validated negative outcomes. A lifecycle cancellation by itself is not proof that the aircraft physically missed the observer.
- **Not recommended:** introducing another live predictor or automatically promoting a candidate during this release.

## Shadow evaluation

The authoritative physical prediction version remains `5.1-3d-proximity`.

For each scoreable outcome, the evaluator can compare:

- current production prediction as the control;
- v4.6 linear shadow candidate;
- v4.6 turn-aware shadow candidate.

Candidate models remain shadow-only. They cannot qualify, cancel, time or send an alert.

Prediction Lab snapshots record the application release version and shadow feature-flag state, making results traceable across releases. Evaluation uses the feature-flag state captured with the original snapshot rather than whatever happens to be configured later. Pre-v5.2 snapshots without a release identifier are explicitly labeled `pre-v5.2-unversioned` instead of being misattributed to the current release.

## Scoreable truth

v5.2 deliberately distinguishes lifecycle events from ground truth.

An observed pass is scoreable only after Plane Alerts has fresh physical evidence of an in-radius pass. A cancellation remains unscoreable unless a later, separately validated negative outcome proves the aircraft did not enter the radius. Missing ADS-B coverage is unresolved and is never converted into either a hit or a miss.

This means some metrics may correctly remain unavailable until their denominator exists. `null` is preferred to a misleading zero.

ETA evaluation uses an explicit physical closest-observation timestamp. When that timestamp exists, it is authoritative. If the physical closest timestamp cannot be matched confidently, CPA/classification can still be scored from verified pass distance, but ETA truth is left unavailable rather than substituting the later lifecycle-resolution time.

## Metrics

The evaluation records and summaries support:

- CPA absolute error / MAE;
- ETA absolute error / MAE only when a physical closest-observation timestamp exists;
- false-positive count/rate when scoreable negative truth exists;
- false-negative count/rate when scoreable positive truth exists;
- cancellation accuracy when resolved cancellation truth exists;
- alert lead time;
- confidence calibration using Brier error against **classification correctness** where a confidence score is available—the existing confidence score is prediction reliability, not probability of a pass;
- horizon-bucket, coverage-mode and ETA-basis distributions;
- release-to-release grouping by application version and model ID.

Evaluation rows are bounded, indexed and TTL-expired after 14 days. Each scoreable live outcome gathers at most 24 recent snapshots and persists its evaluation rows in one unordered Mongo bulk write rather than dozens of sequential optional writes. Error Museum evidence remains separate and permanent.

## Feature flags

Shadow evaluation can be disabled independently without changing the live predictor:

- `PLANE_SHADOW_EVALUATION_ENABLED`
- `PLANE_SHADOW_V46_LINEAR_ENABLED`
- `PLANE_SHADOW_V46_TURN_ENABLED`

All default to enabled for evaluation. None can select a live alert model.

## Promotion policy

A candidate is never automatically promoted because a single metric improves.

The deterministic assessment requires all of the following before a candidate can even be marked eligible for engineering review:

- enough scoreable samples;
- representative horizon coverage;
- comparable false-positive **and** false-negative safety denominators for candidate and control;
- no major safety regression once those rates are comparable;
- successful replay validation;
- successful live shadow validation.

If a required safety denominator is missing, promotion stays on hold. Even when every gate passes, the result is `hold-for-human-review`; `automatic_promotion` remains false.

## Operator tooling

A read-only report is available from the standard image:

```text
planealerts shadow-eval
planealerts shadow-eval --days 7 --limit 2000
```

The command reports model/release metrics, feature-flag state and promotion evidence. It cannot change feature flags, activate a candidate or modify live alerts.

## Replay and performance gates

CI adds:

```text
pytest -q tests/test_shadow_evaluation_v52.py
python scripts/evaluate_v52_shadow_replay.py
python scripts/benchmark_v52_shadow_eval.py
```

The replay fixture includes scoreable observed passes plus intentionally unresolved cancellation and missing-coverage cases. The latter must produce no scored evaluation rows.

The pure deterministic evaluation benchmark must remain below 1 ms p95. Live evaluation executes only from the existing bounded Prediction Lab optional-work path after a scoreable outcome; it does not add provider requests or synchronous work to the five-second alert-critical calculation.

All inherited Error Museum, provider, Telegram, LTFM/LTBA/ISL terminal-arrival, storage, observability, v5.1 geometry, full wrapper-chain, amd64 and ARM64 gates remain mandatory.

## Production acceptance

Production verification must confirm:

- exact tested v5.2.0 main SHA deployed to both Railway services;
- `/health` remains healthy;
- normal five-second monitor cadence;
- no new CPA, wrapper, Prediction Lab or shadow-evaluation exception storm;
- v4.7.3 LTFM/LTBA/ISL protections remain active;
- `planealerts shadow-eval --help` exists in the deployed image;
- scoreable live passes can create bounded evaluation records when such outcomes occur.

If no scoreable pass occurs during the verification window, that is **insufficient live sample evidence**, not proof of success or failure for a candidate model.

## Prediction identity

Application version: `5.2.0`.

Physical prediction version: `5.1-3d-proximity`.

No CPA/ETA threshold, altitude-relevance threshold, route/terminal suppression rule, qualification/cancellation rule or alert timing policy is changed by v5.2.

Runtime AI and AGY remain non-authoritative. No paid runtime service is introduced. The unrelated staged Railway configuration patch is outside this release and remains untouched.
