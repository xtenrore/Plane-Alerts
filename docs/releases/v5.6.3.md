# Plane Alerts v5.6.3 — Permanent Operational Telemetry Boundary

## Scope

v5.6.3 completes the Railway storage recovery started in v5.6.1/v5.6.2. It does not change trajectory, CPA, ETA, destination/path qualification, cancellation semantics, notification timing, or the five-second monitoring cadence.

## MongoDB remains for durable application state

MongoDB remains authoritative for durable user/application data such as users and Telegram identity, configured locations, profiles, preferences/settings, alert/restart state, bounded provider learning, feedback, camera profiles and other configuration/state that requires shared document semantics.

## Persistent volume owns operational telemetry

The existing Plane Alerts persistent volume at `/data/prediction_lab` owns high-volume/reconstructable operational data:

- callsign route history: `/data/prediction_lab/runtime/route_history.sqlite3`
- Prediction Lab audit/shadow/sentinel evidence: file-backed spool under `/data/prediction_lab`
- notification lifecycle/delivery telemetry: `/data/prediction_lab/runtime/notification_history.sqlite3`

Notification telemetry preserves its existing logical lifecycle counters, first-delivery timestamp and bounded last-64 event history. Records expire after 35 days so the Railway volume cannot grow indefinitely.

## One-time migration and retirement

Any surviving `notification_history` Mongo records are copied into the volume SQLite store and count-verified before the Mongo collection is dropped. The obsolete/recreated `flight_route_samples` Mongo shell is also dropped. If migration counts do not match, cleanup does not drop the legacy notification collection and retries outside the alert-critical path.

The runtime storage policy blocks Mongo index creation/accessor use for the known high-volume operational collections:

- `flight_route_samples`
- `notification_history`
- `prediction_lab_audit`
- `prediction_shadow_evaluations`
- `prediction_sentinel_routes`

No user/location/profile/preference/settings collection is enumerated by this cleanup. No retired external-agent/AGY service or volume is restored or reused.

## Release gates

Railway release requires the full applicable CI suite, storage migration regressions, notification lifecycle regressions, Error Museum/lifecycle coverage, performance/cadence benchmarks, exact tested SHA deployment, and production verification that operational Mongo writes/indexes do not return while Mongo user/config reads/writes and the five-second monitor remain healthy.
