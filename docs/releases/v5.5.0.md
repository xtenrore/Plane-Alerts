# Plane Alerts v5.5.0 — Guided Community Self-Hosting

Plane Alerts v5.5.0 is a community self-hosting release built on the verified v5.4.2 production codebase. It does not change the authoritative physical prediction model, which remains `5.3-3d-proximity-age-aware`.

This release is distributed through GitHub Releases for people running their own Plane Alerts instance. It is deliberately separate from the owner's Railway deployment path.

## Guided installers

Release assets include platform-specific entry points:

- `setup.bat` — Windows architecture-detecting bootstrapper.
- `setup-windows.bat` — Windows x64 / AMD64.
- `setup-windows-arm64.bat` — Windows ARM64.
- `setup-linux.sh` — Linux x64 / AMD64 on supported Debian/Ubuntu-family systems.
- `setup-linux-arm64.sh` — generic Linux ARM64.
- `setup-raspberry-pi.sh` — Raspberry Pi 4/5-class 64-bit systems.
- `SHA256SUMS.txt` — SHA-256 checksums for the installer assets.

The Windows dispatcher verifies the downloaded architecture-specific installer against the release checksum before executing it. Platform installers resolve and clone the latest stable semantic-version GitHub release tag rather than following `main`.

## Guided setup

The shared installer provides a numbered setup/maintenance menu and performs real validation before it installs the background service. It supports:

- Local Database / SQLite as the recommended personal self-hosting option.
- MongoDB Atlas.
- Existing MongoDB servers.
- Telegram BotFather token setup with live Telegram authentication validation.
- Optional OpenSky OAuth2 client credentials using the existing Plane Alerts `clientId:clientSecret` or JSON format.
- Optional local readsb, dump1090, dump1090-fa, or ultrafeeder HTTP aircraft feeds.
- Automatic stable updates or manual update mode.
- Repair, configuration changes, diagnostics, update and uninstall flows.

Local receiver coordinates are receiver-coverage metadata only. They are not substituted for Telegram alert profile locations. Users continue to create and edit actual monitoring locations through Plane Alerts profiles in Telegram.

## Local SQLite persistence

v5.5 introduces a first-class SQLite document backend for self-hosting. It implements the Mongo-style async storage operations Plane Alerts needs for critical collections, including query/update semantics, sorting, projections, unique indexes, TTL cleanup, schema migration state, restart persistence, integrity checks and consistent backup support.

SQLite is selected explicitly with `DATABASE_BACKEND=sqlite`; it is not disguised as a MongoDB URI. MongoDB remains a supported explicit backend.

## Community diagnostics

The v5.5 doctor is backend-aware. It validates the selected database backend, schema/integrity, Telegram authentication, public providers, OpenSky configuration and optional local receiver without printing secrets or exact private coordinates.

Sanitized support bundles redact tokens, passwords, authorization headers, MongoDB credentials and receiver coordinates.

## Updates, backups and rollback

The community updater only follows stable GitHub releases. Before changing code it runs preflight diagnostics, refuses tracked local source modifications, backs up `.env`, records the current commit/tag and creates a consistent SQLite backup when SQLite is in use.

The target release is checked out by its immutable tag commit, dependencies are reinstalled from the exact pinned lock, diagnostics are rerun, the service is restarted and live diagnostics must succeed. If target validation fails, the installer restores the previous commit/configuration and SQLite backup and restarts the previous runtime.

Automatic updates use a daily Windows Scheduled Task or systemd timer. They never follow repository `main` directly.

## Background runtime

Community services start `app.community_main_v55:app` and are configured to restart automatically after crashes and machine restarts. Windows uses Task Scheduler; Linux and Raspberry Pi use systemd.

## AGY exclusion

AGY is intentionally not part of the community installer or community runtime:

- no AGY credential prompt,
- no AGY environment configuration,
- no AGY worker/service installation,
- no AGY diagnostics,
- no AGY Telegram command registration,
- no AGY startup/restart/update action.

The community runtime installs a zero-capability console stub before loading the shared Plane Alerts application so the private AGY console is not imported by the self-hosted service.

## Railway isolation

This community release is built and published from the dedicated `release/community-self-hosting-v5.5` branch. The existing Railway deployment workflow remains restricted to successful tested `main` pushes. Publishing this GitHub community release does not deploy or restart either Railway service.

## Validation

The release gate includes the full Plane Alerts test/replay/benchmark workflow plus dedicated community-installer checks. Community CI covers native Linux x64, native Linux ARM64, native Windows x64 and native Windows ARM64 dependency/runtime tests, a Raspberry Pi 5 64-bit platform-guard simulation under ARM64 QEMU, an ARM64 container build, SQLite restart/migration/backup behavior and explicit AGY-exclusion assertions.

The Raspberry Pi platform-guard simulation is not presented as physical Raspberry Pi hardware certification. The Pi installer therefore keeps clear platform checks and emits warnings outside its primary Pi 4/5 targets.

## Prediction behavior

v5.5.0 does not intentionally change trajectory, CPA, 3D proximity, ETA, confidence, route-history inference, terminal-arrival logic, qualification, cancellation or alert timing. The prediction version remains:

`5.3-3d-proximity-age-aware`
