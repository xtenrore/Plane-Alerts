# Plane Alerts v5.8.4 — Storage Maintenance Recovery

## Change

Production v5.8.3 kept retrying background storage maintenance every two minutes with `NotImplementedError`. The maintenance entry point still called the older Prediction Lab Mongo exporter even though operational telemetry had moved to persistent-volume storage and the retired Mongo collections are handled by a separate bounded cleanup task.

The entry point now skips that obsolete exporter when the persistent-volume retirement policy is authoritative. It still runs the existing migration path when that policy is unavailable, and SQLite continues through its own path. User, profile and settings Mongo collections are unaffected. No prediction, CPA, ETA, alert qualification, cancellation, Telegram behavior or provider selection changes. Prediction version stays `5.3-3d-proximity-age-aware`.

## Validation and release scope

The change includes focused tests for the authoritative-volume path, the legacy fallback and SQLite. The Railway release requires full application CI, relevant storage regressions, cadence and production readiness checks. No dependency, configuration, schema, installer or updater change is required.

COMMUNITY IMPACT: self-host Mongo installations that use persistent-volume operational telemetry follow the same retirement shortcut. The weekly Community Release workflow owns the full self-host database, migration and platform matrix; this Railway release does not claim that matrix passed.
