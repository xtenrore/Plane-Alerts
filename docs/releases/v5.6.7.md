# Plane Alerts v5.6.7 — Prediction Lab Spool Drain & Storage Backpressure

Plane Alerts v5.6.7 is a Railway reliability patch for the persistent-volume incident discovered after v5.6.6.

## Production evidence

v5.6.6 safely reclaimed about 83 MB by removing only an incomplete, unverified historical operational export. The service recovered, operational SQLite initialized and file-backed telemetry resumed. The recovery was temporary: within hours the 500 MB Prediction Lab volume again reached zero free bytes and production logged repeated `OSError: [Errno 28] No space left on device` failures from optional Prediction Lab writes.

The remaining volume consumer was the raw Prediction Lab spool. It contained tens of thousands of small unsynced evidence files. The repository sync workflow was also demonstrably broken: a successful scheduled run selected zero files even while `/raw` contained a large backlog. Inspection of the Railway CLI contract showed the workflow was over-parsing returned JSON paths instead of using the selected-volume-relative directory and file name.

## v5.6.7 changes

- The Prediction Lab sync runs every five minutes instead of every ten minutes.
- The sync parser consumes Railway's top-level `files` array directly and rebuilds every child path from the directory actually listed plus the returned file name. It no longer trusts a mount-absolute path for subsequent volume operations.
- A bounded batch may contain up to 500 evidence objects and 25 MiB, with bounded parallel download/acknowledgement workers.
- Evidence acknowledgement still occurs only after validation and a successful push to `prediction-lab-data`; there is no direct deletion of unsynced evidence.
- When disk headroom is low, frequent routine analytical records such as prediction snapshots and sentinel polls are shed before creating tempfiles. Important outcomes/evaluations remain eligible until the critical reserve is reached.
- Below the critical reserve, all optional Prediction Lab writes are shed so analytical telemetry cannot consume the last operational disk space.
- Low-space/ENOSPC reporting is rate-limited so an optional evidence outage cannot create a traceback storm.
- Existing unsynced raw JSON evidence can be losslessly compacted into an atomically written, read-back-verified NDJSON bundle. Originals are unlinked only after bundle verification. This preserves evidence while turning thousands of tiny files into efficiently drainable objects.

## Safety boundaries

v5.6.7 does **not** delete unsynced evidence merely to create space. It does not select route-history SQLite, notification-history SQLite, state files, user/profile/location/settings data or durable application MongoDB data for cleanup.

No trajectory, CPA, ETA, confidence, destination/path qualification, pass/no-pass, cancellation logic or alert timing is changed. The physical prediction version remains `5.3-3d-proximity-age-aware`.

Missing or intentionally shed optional analytical evidence is treated as unknown, never as a successful prediction or a miss. Important cases remain reconstructable from production logs when file-backed evidence is unavailable.

## Required production verification

The release is successful only if all of the following are observed after deployment:

1. the scheduled evidence sync selects a non-zero `/raw` batch when backlog exists;
2. validated evidence is pushed before remote acknowledgement;
3. acknowledged/compacted evidence begins reducing persistent-volume use;
4. free disk space rises above the protected reserve and remains bounded;
5. repeated `ENOSPC` Prediction Lab traceback storms stop;
6. route-history and notification SQLite remain healthy;
7. the five-second aircraft monitor remains healthy;
8. no Mongo quota-write storm returns;
9. no Telegram alert or prediction-behavior regression appears.
