# Plane Alerts v5.6.4 — Idempotent Operational Mongo Retirement

Plane Alerts v5.6.4 is a Railway reliability patch for the v5.6.3 volume-only operational telemetry migration.

## What changed

- Completed operational Mongo retirement is now strictly idempotent.
- The persistent retirement marker is checked before acquiring a Mongo handle.
- Once the marker confirms `notification_history` and `flight_route_samples` were retired, normal runtime execution never reopens Mongo for that cleanup.
- The background retirement task cannot be recreated repeatedly after successful completion.
- Regression coverage proves a completed retirement marker prevents Mongo access and prevents cleanup task rescheduling.

## Storage boundary

MongoDB remains for durable application/user state such as users, Telegram identity, locations, profiles, preferences/settings and configuration.

High-volume operational telemetry remains on the Plane Alerts persistent Railway volume. No retired external-agent resource or integration is restored.

## Prediction safety

No trajectory, CPA, ETA, qualification, cancellation, destination-path or alert-timing logic changes in v5.6.4.

## Production verification

After deployment verify:

1. No Mongo quota errors occur.
2. No repeated `Operational Mongo telemetry retired` messages are emitted during normal notification processing.
3. Route/notification/Prediction Lab telemetry remains volume-backed.
4. User/profile/location/config data remains available from MongoDB.
5. The five-second monitor cadence remains healthy.
