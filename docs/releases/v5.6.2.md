# Plane Alerts v5.6.2 — Legacy Mongo Retirement

## Scope

v5.6.2 is a Railway reliability follow-up to v5.6.1. It does not change deterministic trajectory, CPA, ETA, destination-path qualification, cancellation, or alert timing.

## Permanent storage boundary

MongoDB remains authoritative only for durable application/user data such as users, Telegram identity, configured locations, profiles, preferences/settings, and related configuration.

High-volume operational telemetry remains permanently volume-backed. Callsign route history uses `/data/prediction_lab/runtime/route_history.sqlite3`; Prediction Lab audit, shadow and sentinel evidence remains file-backed under the Plane Alerts persistent volume. These runtime writers must not fall back to MongoDB.

## Legacy cleanup

The remaining live sentinel path no longer retries historical Prediction Lab Mongo exports when file-backed storage is authoritative. This removes repeated Atlas timeout/error noise from the live sentinel loop.

Retirement of the reconstructable legacy `flight_route_samples` Mongo collection is scheduled from the running event loop instead of depending on a later aircraft sample. The migration may import readable recent route rows first, but failure to read old operational telemetry does not block retiring that non-user collection.

No user/profile/location/preference/settings collection is part of this cleanup. No retired external-agent runtime or volume is restored or reused.

## Validation

Release requires the full Railway CI workflow, exact-head merge, exact deployed commit verification, healthy five-second monitoring cadence, no `flight_route_samples` Mongo write storm, no repeated `prediction_lab_mongo_migration_failed` sentinel loop, and preserved Mongo-backed user/config behavior.
