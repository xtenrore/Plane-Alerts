# Plane Alerts v5.4.1 — AGY Reliability Hotfix

Plane Alerts v5.4.1 is a focused AGY-side reliability patch. It does not change trajectory, CPA, ETA, qualification, cancellation, airport/terminal logic, alert timing, provider polling, or the physical prediction version.

## Fixed

- **PA-A03 — quota hold survives startup overrides.** A persisted AGY quota wait now dominates enable/re-enable, force-run tokens, deployment/startup markers, tooling-policy migration, and supervisor recovery. Interactive console launch is also blocked while a durable quota hold is active.
- **PA-A04 — conservative quota recovery parsing.** Compound reset durations, multiple applicable reset windows, and absolute timestamps are handled completely. Automatic retry is scheduled only from a verified reset deadline and always includes the mandatory 10-minute guard. Unknown/ambiguous reset text enters an unverified quota hold instead of assuming a five-hour recovery.
- **PA-A08 — fair AGY context refresh.** Mongo failures are isolated per context collection so a timeout in `notification_history` cannot starve profiles, route history, prediction audit, or other independent evidence. Cached evidence exposes collection-level freshness and retry state.
- **PA-A14 — authoritative profile input.** AGY now reads the canonical `profiles` collection and preserves the existing privacy sanitization and persisted fallback behavior.
- **PA-A15 — lossless findings pagination.** `/findings` returns the earliest next ordered page after the cursor and advances only through records actually returned, preventing older unhandled sequences from being skipped.

The tooling-recovery wrapper was also brought under the same durable quota invariant so a denied-tool recovery turn cannot bypass a verified or unverified quota hold.

## Safety invariants

- Paid AGY credit overages remain disabled.
- AGY inference is not used for runtime trajectory, CPA, ETA, qualification, cancellation, or alert timing.
- The prediction version remains `5.3-3d-proximity-age-aware`.
- Regression tests use fake/offline subprocess behavior and do not launch AGY inference.
- Normal Plane Alerts deployment continues to exclude the AGY Railway service; any AGY deployment requires separate quota-safe verification.

## Verification

Release acceptance requires the full repository test suite, Error Museum/replay suites, inherited benchmarks, dependency checks, amd64 image checks, ARM64 build, GitHub CI, exact-main deployment verification, and separate non-inference AGY production verification where safely possible.
