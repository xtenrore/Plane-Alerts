# Plane Alerts v5.5.2 — Railway Volume CLI Compatibility Patch

Plane Alerts v5.5.2 is a release/deployment compatibility patch for the file-backed Prediction Lab architecture introduced in v5.5.1.

The v5.5.1 code, replay, benchmark, self-hosting and installer gates all passed, and its immutable release was published. Its Railway production deployment then stopped before application deployment while ensuring the new persistent Prediction Lab volume because the current Railway CLI rejected target selectors placed after the `volume list` subcommand.

## Fix

The production deployment workflow now uses the current Railway CLI target grammar:

```text
railway volume --project <project> --service <service> --environment <environment> list --json
railway volume --project <project> --service <service> --environment <environment> add --mount-path /data/prediction_lab --json
```

The scheduled Prediction Lab synchronization workflow uses the same parent-level selector ordering for volume discovery and for `volume files` list/download/rename operations. Spool files are still acknowledged only after validated evidence has been committed and pushed successfully to `prediction-lab-data`.

A regression test rejects the failed `railway volume list --project ...` form and asserts the verified parent-selector command structure in both deployment and synchronization workflows.

## Scope and safety

This patch does not change:

- the Prediction Lab evidence schema or durable case/checkpoint contract,
- MongoDB export/count/SHA verification or retirement rules,
- the eight fixed high-risk sentinel areas or privacy-safe delegated-admin sampling,
- `/next60` shadow/evaluation semantics,
- ADS-B ingestion, trajectory, CPA, ETA, confidence, route/terminal logic,
- qualification, cancellation or alert timing,
- the physical prediction version (`5.3-3d-proximity-age-aware`).

No paid AI/API dependency is introduced and runtime AI remains outside the physical prediction path.

## Deployment and migration

The corrected workflow must first ensure the Railway persistent volume at `/data/prediction_lab`, then deploy the exact tested `main` commit. On first successful v5.5.x production startup, the application performs the verified Prediction Lab MongoDB export before retiring only the legacy high-volume Lab collections. Normal application/user/configuration MongoDB data remains in MongoDB.

Production verification must confirm the migration/archive integrity, file-backed evidence writes, bounded Git synchronization, and healthy five-second monitoring cadence before this patch is considered complete.

## Update and rollback

v5.5.2 is the sequential patch after the immutable v5.5.1 release. Existing v5.5.1 release assets and tag are not modified.

If production rollout fails a release gate, do not treat the failed deployment as complete. The previous production code remains the rollback target until v5.5.2 is verified. Prediction Lab archive data already exported to the persistent spool or Git evidence branch must be preserved across rollback; normal MongoDB application data must not be removed.
