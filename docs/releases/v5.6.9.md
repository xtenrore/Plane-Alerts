# Plane Alerts v5.6.9 — Live Service Filesystem Prediction Lab Drain

Plane Alerts v5.6.9 is a Railway storage-recovery patch following the first production execution of the v5.6.8 repository-acknowledged spool drain.

## Production finding

The v5.6.8 workflow bootstrapped immediately from the merge as intended. Railway authentication succeeded and the Prediction Lab volume attachment was found, but the selected-volume SFTP target failed while listing `/raw`. The failure occurred before validation, repository push, acknowledgement or deletion, so no unsynced evidence was lost.

Railway's CLI implementation confirms that volume-file commands internally prefix the selected volume mount path. Railway also exposes a supported `service files` command that addresses the filesystem exactly as the running service sees it. That service target uses `/` as its SFTP root, so the mounted Prediction Lab volume is addressed directly as `/data/prediction_lab/...`.

## v5.6.9 behavior

The Prediction Lab synchronization workflow now:

- confirms that a volume is attached exactly at `/data/prediction_lab` before attempting transfer;
- uses `railway service files` with explicit project, environment and service selectors for list, download and delete operations;
- lists `/data/prediction_lab/raw` and, only when its manifest is verified, `/data/prediction_lab/archive/mongo-import`;
- reconstructs child paths from the exact directory listed plus Railway's returned file name;
- converts absolute service paths back to repository-relative `raw/...` or `archive/...` paths only after proving they remain under the Prediction Lab mount;
- prints the underlying Railway command output when a list operation fails instead of collapsing it to `CalledProcessError`;
- preserves the v5.6.8 bounded 500-object / 25 MiB transfer, validation, repository push, push-before-delete acknowledgement and serialized self-drain chain.

The acknowledgement step additionally refuses any remote path outside `/data/prediction_lab/raw/` and `/data/prediction_lab/archive/mongo-import/`.

## Safety boundaries

No remote evidence file can be removed before successful validation and repository acknowledgement. A failed list, download, validation, rebase or push stops before destructive cleanup.

The workflow never selects route-history SQLite, notification-history SQLite, state files, user/profile/location/settings data or durable application MongoDB collections for removal.

No trajectory, CPA, ETA, confidence, destination/path qualification, pass/no-pass, cancellation or alert-timing behavior changes. The prediction version remains `5.3-3d-proximity-age-aware`.
