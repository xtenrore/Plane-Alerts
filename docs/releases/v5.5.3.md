# Plane Alerts v5.5.3 — Startup Migration Isolation

## Summary

v5.5.3 fixes the production-readiness regression exposed by the v5.5.2 Railway deployment. The application successfully connected to MongoDB, but FastAPI startup remained blocked while the one-time v5.5 Prediction Lab historical archive migration, normal index maintenance and schema maintenance ran synchronously. Railway therefore never received a healthy `/ready` response within its deployment health window.

## Changes

- Railway now treats the Prediction Lab historical archive migration plus Mongo index/schema maintenance as low-priority background maintenance after a normal Mongo connection is established.
- FastAPI startup and the live monitoring runtime no longer wait for that historical maintenance to finish.
- Background maintenance retries failures with bounded exponential backoff rather than terminating the application runtime.
- The same verified migration implementation remains authoritative: historical Prediction Lab collections are exported with record counts and SHA-256 integrity checks before they are retired.
- Prediction Lab Git synchronization now ignores historical archive chunks until the archive manifest itself reports `verified=true`, preventing an interrupted migration from publishing partial history.
- Normal application MongoDB data remains untouched by the Prediction Lab migration.
- Non-Railway/default self-host execution keeps the existing synchronous maintenance gate unless the background-maintenance override is explicitly enabled.
- Shutdown cancels the maintenance task before the database client is closed.
- Added regression coverage proving Railway startup does not await a blocked migration, transient maintenance failures retry to completion, and archive synchronization is verification-gated.

## Prediction behavior

No physical prediction logic changes in this release. Trajectory, CPA, ETA, confidence, terminal logic, qualification, cancellation and alert timing remain deterministic and unchanged.

Prediction version remains:

`5.3-3d-proximity-age-aware`

## Configuration

No new required configuration is introduced. Railway automatically uses background storage maintenance. Operators can explicitly override this internal behavior with `PLANE_STORAGE_MAINTENANCE_BACKGROUND` when diagnosing storage maintenance, but normal installations do not need to set it.

## Installer / self-hosting

No installer prompts, dependencies, database schema format, service start command or provider configuration change. Existing v5.5 installer and rollback behavior remains compatible.

## Rollback

If v5.5.3 fails production verification, roll back to the previously healthy production deployment. Do not move or overwrite the immutable v5.5.3 tag after publication; publish a new patch release for any subsequent correction.
