# Plane Alerts v5.1.3

Plane Alerts v5.1.3 completes the production compatibility repair for the v5.1 3D predictor wrapper chain. It restores the intended `5.1-3d-proximity` model through every legacy wrapper installed in production and does not introduce a new physical prediction model.

## Fixed

Production verification of v5.1.2 exposed an additional live failure below the already-fixed v4.6 confidence wrapper:

`TypeError: predict_trajectory_v44() got an unexpected keyword argument 'altitude_relevance'`

The real installed chain is:

`core v5.1 trajectory -> v4.3 midpoint wrapper -> v4.4 direct-presence guard -> v4.6 confidence wrapper -> critical timing`

v5.1.3 updates the v4.4 and v4.3 wrappers to accept and forward the current v5.1 `altitude_relevance` argument. Unknown observer elevation remains `None` through the authoritative v5.1 3D predictor. The older v4.3 slant-distance diagnostics continue to use a numeric nominal fallback only for their legacy local calculation, avoiding the previous `float - None` crash without changing authoritative elevation semantics.

The full-chain regression also exposed two legacy semantic overrides. The v4.3 midpoint wrapper previously rebuilt `enters_alert_radius` from horizontal geometry after the v5.1 core had applied trustworthy 3D relevance, and it retained the old projected-CPA shortcut for `already_passed`. v5.1.3 now recomputes deterministic 3D relevance on the actual midpoint-adjusted production path and preserves the v5.1 observed-pass requirement. The v4.4 direct-presence guard no longer overrides a trustworthy altitude exclusion or an already-observed completed pass.

## Regression protection

The compatibility test now recreates the complete installed wrapper chain rather than stopping at v4.6. It verifies:

- `altitude_relevance=False` reaches the authoritative v5.1 predictor;
- `altitude_relevance=True` reaches the authoritative v5.1 predictor and remains effective after midpoint recomputation;
- a fresh horizontal in-radius observation cannot override a trustworthy v5.1 3D exclusion;
- unknown observer elevation remains unknown through the full stack;
- both the v4.3 and v4.4 wrappers accept the current v5.1 signature;
- a projected CPA alone is not restored as proof of a completed pass;
- an actually observed in-radius pass remains passed through every wrapper.

All inherited terminal-arrival, LTFM/LTBA/ISL, Error Museum, storage, provider, Telegram, self-hosting and performance gates remain mandatory.

## Prediction identity

Application version: `5.1.3`.

Physical prediction version remains `5.1-3d-proximity`.

No CPA/ETA threshold, route/terminal suppression rule, qualification/cancellation rule or alert timing policy is changed by this hotfix. The changes make the installed legacy wrappers preserve the already-defined v5.1 geometry and lifecycle semantics. Runtime AI and AGY remain non-authoritative for trajectory and alert decisions. No paid runtime service is introduced.

## Production acceptance

Before v5.2 begins, both Railway services must run the exact tested v5.1.3 commit. Main-service verification must show:

- healthy startup and `/health`;
- no new `predict_trajectory_v43`, `predict_trajectory_v44` or `predict_trajectory_v46` unexpected-keyword failures;
- no ongoing `cpa_calculation_failed` exception storm;
- normal five-second monitor cadence;
- healthy Telegram/runtime startup;
- no regression in LTFM/LTBA/ISL terminal-arrival protections.

Missing ADS-B coverage remains unresolved rather than being counted as prediction success or failure.

The unrelated staged Railway configuration patch is outside this source release and must remain staged and untouched during v5.1.3 deployment.

## Rollback

v5.1.2 is known to fail live CPA calculations in the v4.4 wrapper and is not a healthy rollback target. If rollback is required, use the most recent production-verified release before the v5.1 wrapper incompatibility rather than knowingly restoring the error storm.
