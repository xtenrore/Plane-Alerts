# Plane Alerts v5.8.2 — Route Guard Consolidation

## Scope

This release completes Release 1 of the Architecture & Product Improvement roadmap by consolidating Plane Alerts route-guard authority into one canonical non-versioned module.

Production v5.8.1 already mounted only the provider-first destination/path guard introduced in v5.5.4. The older `route_guard.py`/v2/v4.2/v4.7 stack and its requalification/arrival compatibility shims remained in the repository but were not installed by the live worker. v5.8.2 moves the exact production authority into `app/intelligence/route_guard.py`, updates the live worker and benchmark to use it, and removes the obsolete generations rather than reviving historical behavior.

## Behavior preservation and regression coverage

No prediction threshold or alert policy is intentionally changed. The canonical implementation preserves bounded background destination lookup and the existing deterministic decision rules:

- fresh physical entry inside the configured radius remains authoritative;
- provider outage or genuinely ambiguous destination disagreement fails open to live trajectory;
- a new candidate may be held for one monitor cycle while bounded destination lookup is pending, but an existing alert is not cancelled only because lookup is pending;
- terminal arrival may be vetoed when the known destination/landing area is physically reached before the projected observer pass;
- sustained divergence, diversion or go-around evidence releases destination suppression;
- missing or stale evidence is not treated as proof that a prediction succeeded or failed.

The route-guard regression suite covers normal projected passes, IST/LTFM and LTBA/ISL terminal arrivals, genuine pass-before-airport geometry, late destination resolution after initial qualification, route-veto true/false transitions, go-around/diversion recovery, provider conflict/outage, stale/missing evidence, physical-radius override and non-blocking slow-provider behavior. Existing Error Museum and terminal-classifier suites remain in place. A new architecture test rejects the removed route-guard module names and imports if they are reintroduced.

The prediction identity remains `5.3-3d-proximity-age-aware`.

## Community impact and rollback

Plane Alerts runtime configuration, dependencies, environment variables, storage schema, migrations, providers, service command, health endpoints, installer prompts and updater behavior do not change. The weekly Community Release workflow should run its accumulated application/installer/platform validation before any later community-stable publication; this Railway release does not claim Windows ARM64, Linux ARM64, Raspberry Pi or fresh-install validation.
