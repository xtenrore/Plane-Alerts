# Plane Alerts v6.0.0 — Private AI Operations Phase 0

## Scope

v6.0.0 is the first release boundary of the Private AI Operations roadmap.

This release completes **Phase 0 — Baseline, Inventory & Design Lock** only. It does not start Phase 1.

## What changed

- recorded the exact Plane Alerts source and Railway production baseline;
- verified production remains healthy on Plane Alerts 5.8.7 at the same tested commit used by `main`;
- inventoried current Railway services, persistent volumes, database/storage roles, health/readiness, provider configuration, release workflows, and scheduled-task ownership;
- documented the current AI-provider capability pre-screen without making a live LLM inference call;
- locked Private AI Operations to a separate private Railway service with its own persistent volume instead of reusing the space-constrained Prediction Lab volume;
- selected SQLite WAL as the Phase 1 orchestration store;
- defined the Phase 1 job/step/attempt/lease/idempotency/scheduler schema contract and initial bounded retention targets;
- reserved `xtenrore/Plane-Alerts-Private-State` as the future dedicated private disaster-recovery repository, to be provisioned in Phase 2;
- added `docs/private-ai-ops/implementation-state.json` so future sessions can resume from durable status rather than chat memory.

The full Phase 0 decision record is in [`docs/private-ai-ops/phase-0-baseline.md`](../private-ai-ops/phase-0-baseline.md).

## Safety

No live provider router, AI job engine, hourly AI audit, Supervisor Chat, GUI, backup worker, or production mutation control is introduced in this phase.

Runtime AI remains outside the deterministic alert-critical path and cannot decide trajectory, CPA, ETA/TTC, pass/no-pass, qualification, cancellation, CAMERA READY, PHOTO NOW, or alert timing.

No paid model call was made. No provider inference call was required for Phase 0. No secret values or private coordinates are stored in the Phase 0 artifacts.

## Production and community impact

The v6.0.0 Phase 0 branch is documentation/design-state plus release identity only. It changes no dependency, environment-variable contract, database schema, installer behavior, Telegram behavior, ADS-B provider behavior, prediction geometry, or alert lifecycle.

The full community/self-host platform matrix remains owned by the weekly Community Release workflow. This Phase 0 work does not claim that matrix was run.

## Deployment status

Phase 0 is built on `release/v6.0.0-phase0`.

It is intentionally not merged or deployed as part of the Phase 0 build request. Production remains on the verified 5.8.7 baseline until the normal release gate is explicitly completed.

## Next phase

Phase 1 will be **Durable AI Ops Storage & Job Engine** and is intentionally not started by v6.0.0 Phase 0.
