# Plane Alerts v5.4.2 — General Reliability Audit Fixes

Plane Alerts v5.4.2 fixes the remaining non-AGY findings from the verified 2026-09-21 general bug audit. The physical prediction version remains `5.3-3d-proximity-age-aware`.

## Fixed findings

- **PA-A01:** successful first-time profile setup now marks monitoring complete only after the required profile/materialization writes succeed. Failed or cancelled setup remains incomplete, while ordinary edits do not override a deliberate monitoring disable.
- **PA-A02:** active-profile changes preserve a coherent last-known-good configuration across partial materialization failures. The authoritative profile is not committed ahead of a failed legacy materialization, warm refreshes retain the previous coherent per-user generation, and a cold restart can repair a torn materialization from the authoritative active profile.
- **PA-A05:** blank optional `ADMIN_TELEGRAM_ID` values in the shipped environment template parse as `None`; nonnumeric nonblank values remain invalid.
- **PA-A06:** sensitive admin APIs fail closed when `ADMIN_PASSWORD` is missing or blank. Blank credentials no longer create root-open access.
- **PA-A07:** Docker Compose rollout health uses `/ready` rather than liveness-only `/health`. Railway production readiness must use the same endpoint for this release.
- **PA-A09:** the v4.6 interaction layer is installed explicitly during a fresh runtime import after the required Telegram modules exist, so ACK-before-I/O behavior and the replacement Next 60 callback are active in normal startup.
- **PA-A10:** observer-elevation enrichment is queued from the actual cached live-user path, remains nonblocking, is bound to the exact saved coordinates, and invalidates cached configuration only after a matching-location write succeeds.
- **PA-A11:** preset creation Save buttons are bound to one persisted draft session. Stale or duplicate callbacks cannot consume a newer edit draft or create/activate an unintended profile.
- **PA-A12:** retained photography snapshots preserve absolute observation age. Historical notification positions are not reconstructed as fresh trajectory observations or used for a current shooting countdown.
- **PA-A13:** untargeted `/photo` aircraft selection reuses the canonical deterministic profile filter, including category/type, airline, altitude, enable/disable, exclusion and radius rules. Explicit notification targeting remains separate.
- **PA-A16:** profile validation now evaluates inherited effective altitude rules so category/type minima cannot silently exceed inherited maxima.
- **PA-A17:** user-facing help, photography branding and the admin session product version use the canonical Plane Alerts release version; the v3.6 admin API schema remains separately labelled.

## Safety boundaries

This patch does **not** intentionally change trajectory geometry, CPA, ETA, confidence, qualification, cancellation thresholds, terminal-arrival guards, provider polling, notification timing, or the physical prediction model.

Runtime AI remains outside geometry, CPA, ETA, pass/no-pass and alert timing. No paid AI/API dependency is added. The separate AGY service is excluded from the normal Plane Alerts deployment path.
