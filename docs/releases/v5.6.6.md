# Plane Alerts v5.6.6 — Critical Volume Recovery

Plane Alerts v5.6.6 is an emergency Railway reliability patch following the v5.6.5 production verification failure.

## Production finding

The Plane Alerts persistent volume reached zero free bytes. v5.6.5 correctly found no repository-acknowledged `*.synced` evidence available to prune, so it refused to delete unsynced evidence or runtime databases.

The Prediction Lab sync workflow also reported that the historical `archive/mongo-import` export was not verified. The migration implementation makes that boundary explicit: the archive is authoritative only after a manifest with `verified: true` is successfully written. An incomplete archive is a temporary sanitized copy of retired operational telemetry, not user data and not a valid backup.

## Recovery behavior

When the Plane Alerts volume is critically low on space, v5.6.6:

- reads a volume inventory before cleanup;
- checks the local historical-export manifest;
- permanently protects the archive when its manifest is verified;
- when the archive is missing a verified manifest, removes only that incomplete `archive/mongo-import` export;
- then applies normal repository-acknowledged `*.synced` pruning;
- records before/after disk usage plus category and largest-file diagnostics.

The emergency recovery never selects:

- raw unsynced Prediction Lab evidence;
- route-history SQLite or its runtime directory;
- notification-history SQLite or its runtime directory;
- state files;
- MongoDB durable user/application collections;
- user locations, profiles, preferences/settings or configuration.

Recovery runs before the sentinel network's initial delay so space can be reclaimed before normal file-backed shadow collection resumes.

## Prediction safety

No trajectory, CPA, ETA, destination qualification, alert qualification, cancellation logic or alert timing is changed.

## Production verification

The release is successful only if production proves that:

1. the cleanup either reclaims meaningful space or the inventory identifies a different exact consumer;
2. `ENOSPC` / `No space left on device` errors stop if space is reclaimed;
3. operational SQLite stores initialize normally;
4. file-backed Prediction Lab writes resume;
5. Mongo quota errors remain absent;
6. the five-second aircraft monitor remains healthy.
