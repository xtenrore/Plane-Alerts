# Plane Alerts v5.8.5 — Mongo Maintenance Truth Testing

## Change

The v5.8.4 deployment confirmed that the retired Prediction Lab exporter was skipped, yet background maintenance still failed with `NotImplementedError` before index creation. Motor dynamically treats the requested `is_plane_alerts_sqlite` attribute on a Mongo database as a collection. Testing that collection with `bool(...)` raises `NotImplementedError`.

The operational index policy now recognizes only the explicit `True` marker on the local SQLite backend. Matching marker checks in database shutdown, local-backend selection and diagnostic backend labeling use the same rule. Mongo indexes and schema maintenance can proceed after the v5.8.4 migration shortcut. The existing permitted collection-index policy remains unchanged.

No physical prediction, alert qualification, ETA, Telegram behavior, provider selection, database schema, dependency, configuration, installer or updater changes. Prediction version remains `5.3-3d-proximity-age-aware`.

## Validation and community impact

The new regression simulates Motor's dynamic collection attribute and truth-value exception through the complete migration → indexes → schema sequence. It also covers shutdown, backend labeling, local-backend switching and normal SQLite markers. Railway release gates require the full application suite, individual CI steps, deployment of the exact tested commit, live storage-maintenance readiness, monitoring cadence and Telegram mode.

COMMUNITY IMPACT: the corrected backend marker checks also run on self-host Mongo and local SQLite installations. Full Mongo/SQLite upgrade and platform checks remain in the weekly Community Release workflow.
