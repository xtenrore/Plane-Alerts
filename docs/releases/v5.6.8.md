# Plane Alerts v5.6.8 — Repository-Acknowledged Spool Drain

Plane Alerts v5.6.8 is a Railway storage-recovery patch that completes the v5.6.7 Prediction Lab backpressure work.

## Production finding

v5.6.7 successfully stopped optional Prediction Lab writes from consuming additional disk once the persistent volume reached the critical reserve. Production verification nevertheless showed the volume was already at zero free bytes, with more than 55,000 raw Prediction Lab files. At that point route-history SQLite and notification-history SQLite could not reliably commit because the filesystem itself had no writable headroom.

The repository sync workflow also could not be trusted to recover promptly from that state through its schedule alone: observed GitHub schedule delivery was substantially less frequent than the declared cadence.

## Recovery behavior

v5.6.8 keeps the v5.6.7 strict discovery, validation and bounded-transfer rules, then changes acknowledgement semantics:

- evidence is downloaded from the Railway volume in a bounded batch;
- every JSON/NDJSON object is validated and checked for credential-like material;
- new repository evidence is committed and pushed to `prediction-lab-data`;
- only after that push succeeds, the exact accepted remote objects are deleted from the Railway volume with Railway's non-interactive confirmed delete operation;
- if the repository already contains byte-identical evidence, that evidence is already authoritative and may be removed from the spool after the same validation step;
- a failed validation, rebase, push or acknowledgement cannot advance to destructive cleanup of unacknowledged evidence.

The workflow remains bounded to 500 objects and 25 MiB per pass with bounded transfer concurrency.

## Backlog continuation

A workflow-file change merged to `main` triggers an immediate bootstrap sync pass so emergency recovery does not depend solely on delayed scheduled delivery.

When a completed pass safely removes at least half of the maximum object batch, the workflow dispatches another bounded `main` sync pass. Existing workflow concurrency keeps those drain passes serialized. The chain stops automatically once a pass is no longer large enough to prove a saturated backlog.

Scheduled five-minute sync remains configured as the steady-state fallback.

## Safety boundaries

v5.6.8 never deletes an evidence object before repository acknowledgement. It does not select route-history SQLite, notification-history SQLite, state files, user/profile/location/settings data or durable application MongoDB collections for deletion.

The v5.6.7 low-space backpressure and lossless NDJSON compaction remain active in the runtime.

No trajectory, CPA, ETA, confidence, destination/path qualification, pass/no-pass, cancellation or alert-timing behavior changes. The prediction version remains `5.3-3d-proximity-age-aware`.

## Required production verification

The release is complete only after production demonstrates that:

1. the main-merge bootstrap starts the sync workflow;
2. `/raw` listing returns real entries and a non-zero bounded batch is selected;
3. validation and repository push complete before any remote removal;
4. acknowledged objects are removed from the Railway volume;
5. large batches dispatch serialized continuation passes;
6. persistent-volume usage falls and writable free space returns;
7. route-history and notification-history SQLite commits recover;
8. Prediction Lab ENOSPC traceback storms remain absent;
9. the five-second aircraft monitor and Telegram readiness remain healthy;
10. no prediction or alert lifecycle regression is introduced.
