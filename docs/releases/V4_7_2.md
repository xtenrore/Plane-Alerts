# Plane Alerts v4.7.2

## Terminal-arrival qualification safety

Plane Alerts v4.7.2 addresses the recurring false-alert class where a low, slow, descending airport arrival temporarily produces a close straight-line CPA toward the observer before making its normal terminal turn.

### Changes

- Added a narrow deterministic **initial terminal-arrival qualification hold** before the first Telegram notification.
- Requires multiple fresh physical signals to agree: terminal-area context, low altitude, reduced speed, sustained descent, closing movement toward the airport and compatible heading/runway evidence.
- Destination metadata is supporting evidence only. `ISL`, `LTBA`, `IST`, `LTFM` or any other destination code can never suppress an alert by itself.
- The initial hold automatically releases for go-around/missed approach, a trajectory change that disproves the expected turn, stale/insufficient evidence, a runway path that can physically reach the observer, or fresh physical entry into the configured radius.
- Once released for an encounter, this v4.7.2 initial gate cannot re-arm to cancel an already-visible alert.
- Added structured Prediction Lab diagnostics for effective/candidate hold state, destination match, evidence age, airport-distance trend and heading error.

### LTBA / ISL Error Museum

The compiled worldwide database is now explicitly release-gated for Istanbul Atatürk Airport identity (`LTBA` / `ISL`) and active runway geometry. The Error Museum includes the exact low/slow/descent failure class: a temporary close straight-line CPA is held before notification, then the alert remains unsent when the aircraft makes the airport turn and the live CPA no longer qualifies.

Regression coverage also proves that `ISL` alone does not suppress an alert and that genuine physical passes, go-arounds, missed expected turns and runway-aligned paths through the observer remain alertable.

### Performance

The terminal-arrival hold is a bounded in-memory calculation on already-available observations. It performs no network or MongoDB work and has a dedicated CI micro-benchmark. The worldwide airport reference database remains local read-only SQLite built from the pinned v4.7.1 OurAirports snapshot.

### Scope

Broad runway/base/final/holding suppression hypotheses remain shadow-only. v4.7.2 promotes only this narrow initial-qualification hold because it has explicit fail-open conditions and regression protection for genuine passes.
